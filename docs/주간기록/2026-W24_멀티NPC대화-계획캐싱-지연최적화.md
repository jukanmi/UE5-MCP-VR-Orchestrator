## 핵심
멀티 NPC 동시 대화를 두 축으로 완성했다. ① **NPC별 e4b 병렬 호출**(`asyncio.gather`)로 지식 격리를 구조적으로 보장하며 다중 발화 — 단일 호출로 모든 페르소나를 한 컨텍스트에 넣을 때의 감정 수렴·지식 누출(A만 아는 비밀을 B가 발화) 오염을 차단. ② **계획 캐싱**("비싸게 계획 1회, 싸게 실행 N회") — cold start 는 풀 파이프라인(e4b×N→12B 정제+plan 산출), warm loop 는 저장된 plan 기반 e4b 단독, C++ 이 perception danger·N턴(5)으로 재계획 판정. 동시에 인지엔진 지연을 대폭 줄였다(SLM Reflex raw 전환 warm 330ms, prompt prefix 재배치 183→37ms, 메모리 기록 fire-and-forget, core 26b→gemma4-12b). 플레이어 측은 음성입력·NPC 조준·HP/인벤토리 HUD 를 붙였고, EQS Failed 고착·Rules 액션 검증 등 안정화. **전부 06-12 집중 작업**, 런타임 검증 일부 대기.

## 메모 (Memo.md Handoff Notes, 2026-06-12)
- **멀티 NPC 병렬 = 지식 격리가 목적**: 단일 호출 묶음은 지식 누출 발화 귀속 추적 불가라 사후 교정 불가 — 병렬 별도 호출이 격리를 구조적으로 보장. `OLLAMA_NUM_PARALLEL=3` 미설정 시 기능은 동작하되 Ollama 가 직렬화해 병렬 효과 없음. 감정 수렴은 `interface_output.py::TRAIT_EMOTION_MAP` 결정론 보정(맵에 없는 trait 미보정). 동시 상한 `MAX_TARGET_NPCS=3`.
- **gemma4-12b 별칭**: `ollama cp hf.co/.../Gemma-4-12B-OBLITERATED-GGUF:Q4_K_M gemma4-12b`. Ollama 재설치 시 재실행. `reasoning=False` 전역 — 12B thinking 이 num_predict 잠식해 content="" 발생, think=false 로 663ms 정상. 26b 코드참조만 제거, 디스크 잔존(`ollama rm` 은 사용자 판단).
- **WS 메시지 동시 처리**: 응답 순서 비보장 — prompt=msg_id, location_decision=request_gen 으로 수신 측 매칭이라 순서 의존 없음. 동시 소켓 쓰기는 `_ws_send_lock` 직렬화.
- **계획 캐싱 staleness 방어**: C++ 트리거 빈약 시 낡은 계획 고집 위험(cf. 과거 자동 Track 무한추적 버그) → N턴(5) 상한이 1차 방어. plan step 소진 트리거는 미구현(ROADMAP §3.4 향후).
