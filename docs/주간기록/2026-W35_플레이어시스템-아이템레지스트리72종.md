① **플레이어 시스템 구현**(08-24) — `SPEC_player_systems` §1~§4 를 하루에 관통했다. Sprint · 인벤토리 HUD 토글 · 월드 픽업 · NPC→플레이어 아이템 전달. 여기서 **GiveItem 아이템 증발 버그**가 같이 잡혔는데, `ExecuteGiveItem` 이 NPC 인벤에서 차감만 하고 수령 쪽엔 아무것도 넣지 않아 전달된 아이템이 월드에서 사라지고 있었다.

에디터 작업도 대부분 `ue_run_python` 으로 처리했다(W34 브리지의 첫 실전 활용) — 6건 중 5건 자동화, WBP 위젯 트리만 파이썬 미노출로 사용자 몫으로 남았다.

③ **아이템 레지스트리 72종**(08-29) — 이 주의 가장 큰 발견이 여기 있다. `DT_ItemRegistry` 의 유일 행이 `Rock` 인데, **v3 SLM 학습데이터 1016건 아이템 언급 중 `Rock` 은 0건**이었다. 반대로 모델이 학습한 75개 ID 중 DataTable 에 있는 건 0개. 즉 GiveItem·HandObject·UseItem·Equip·Trade·Craft **6개 액션이 전부 돌멩이 하나로 수렴**하는 상태였고, 플레이어 시스템 §4 를 구현해도 **줄 물건이 없었다**.

## 주요 작업

### 플레이어 시스템 §1~§4 (08-24, `60411d3`·`da75d4e`·`bbe2e49`)

- **Sprint** — 스틱 magnitude > `SprintThreshold`(0.9) 이면 `SprintSpeed`(600). 별도 입력 액션 없음.
  - **함정**: 해제를 `OnMove` 안에서 못 한다. `Triggered` 는 입력이 0 이 되면 오지 않고 `OnMove` 가 `IsNearlyZero` 에서 조기 return 하기 때문 → `IA_Move` 의 `Completed`/`Canceled`(`OnMoveReleased`)로 해제.
  - Crouching/Prone 은 `ApplyMovementSpeed` 의 자세 분기가 속도를 덮어쓰므로 Sprint 가 자동 억제된다.
- **인벤토리 HUD 토글** — `PlayerHUDWidget` 에 `SetInventoryPanelVisible`/`ToggleInventoryVisibility`. `"InventoryPanel"` 이름 위젯이 있으면 C++ 가 직접 토글, 없으면 WBP 가 처리하는 2단 구조.
- **월드 픽업** — 신규 `APickupItem` 을 만들지 **않았다**. 기존 `ADroppedItemBase` 가 이미 `ItemManager` 등록/해제·InteractionSphere·`ConsumeItem()` 을 갖고 있고 **NPC 아이템 탐지가 그 등록 풀을 본다**. 별도 클래스를 만들면 NPC 가 인지 못 하는 두 번째 월드 아이템 계통이 생긴다.
- **GiveItem 증발 수정**(`60411d3`) — 차감 **전에** `ItemManager::GetItemDataByID` 로 원본 데이터를, `ResolveReceiverInventory` 로 수령처를 모두 확보하고, 하나라도 없으면 NPC 보유분을 건드리지 않고 중단(증발 방지).
- **PR #24**(`bbe2e49`) — W34 의 llm-perf 재구현 머지.

### 에디터 작업 MCP 자동화 (08-24, DoList 1-3)

- **`BP_DropItem` 설정·배치** — 신규 생성 불필요했다(이미 존재, 부모 `ADroppedItemBase`). `TemplateID` `Rock` · 레벨 배치.

## 메모

- **학습데이터와 게임 데이터가 갈라져 있었다** — 모델은 `Bread`/`Bandage` 를 학습했는데 게임엔 `Rock` 만 있었다. 프롬프트 제약("보유 아이템만 GiveItem")이 있어서 모델은 학습한 어휘를 **쓸 수가 없는** 상태였다. 학습데이터를 늘릴 때 게임 데이터도 같이 봐야 한다.
- **alias 맵을 넣지 말 것** — 학습데이터에 표기 변종(`Sword`/`KnightSword`, `Bread`/`BreadLoaf` 등)이 있지만, 런타임은 인벤토리 주입 방식이라 모델이 컨텍스트의 ID 를 그대로 베낀다. 폴백 맵을 넣으면 오타를 정상 동작으로 위장해 데이터 결함을 은폐한다.
- **CSV enum 파싱 실패는 조용하다** — `fill_data_table_from_csv_string` 은 enum 이 안 맞으면 예외 없이 기본값(`General`/`None`)으로 강등한다. 행 수만 세면 못 잡으므로 **저장 전에 엔진 내 분포를 CSV 분포와 대조**할 것. 또 이 함수의 반환값은 에러 리스트가 아니라 **성공 bool** 이다(`True` = 성공).
- **PIE 난이도가 올라갔다** — `Rock` 하나일 땐 GiveItem 이 고를 게 없었지만 이제 Moca 선택지가 9개다. "물 좀 줘"에 `WaterSkin` 을 고르는지가 실제 시험이 된다.
