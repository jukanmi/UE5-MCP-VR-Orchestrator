## 설계 메모 (Notion 개발일기)

### 2026-01-12 — Ollama·Qwen3 NPC 초안
- **폴더 정리 원칙**: 기능 중심 분류 + UE 관례대로 헤더 `Public/` 구현 `Private/`. 이유 — ① 독립 단순화 ② 모두 Public이면 재컴파일 폭증 ③ h만 보면 기능 파악·내부 헤더는 숨김.
- **NPC 초안 3계층**: ① LLM Client(Ollama 통신) ② Brain(LLM→상태머신 명령 변환, 주변 상황 텍스트화) ③ State Machine(Idle/Move/Attack/Flee/Dialogue).
- **Qwen3 로컬 채택 이유**: *"매 순간 AI에 요청하면 로컬로 돌려서 컴퓨터가 터질 수 있기 때문"*. → 이후 모든 SLM·캐싱·EQS 분담 정책의 출발점.
- **삽질**: 채팅 UI BP 안 뜨는 버그 — 토글 IA·AddToPlayerScreen 다 실패 → "BP가 아니라 클래스가 들어가 있어서". *"크,악 내일해야겠다"*.

### 2026-01-17 — 멀티 에이전트 LLM 아키텍처 연구 (학위 연구 출발점)
연구 목표 6항목으로 프로젝트 이론 골격 정립:
1. MCP로 4개 LLM 역할 컨텍스트 분리 오케스트레이션
2. VR 입력(음성·행동) → Semantic Tag → Mediator LLM 맥락 해석
3. 규칙·판정 LLM의 authoritative state 참조 + JSON 결정론 출력
4. LLM 출력 ↔ Blackboard·이벤트 큐 ↔ Behavior Tree 매끄러운 액션
5. 실시간 상호작용 레이턴시가 VR 몰입도에 미치는 영향
6. 단계적 개발 로드맵

**4개 Agent 정의** (이후 코드의 직접 청사진)
| Agent | 역할 | 핵심 도구 |
|-------|------|-----------|
| Narrative (World) | 스토리·퀘스트·장면 | `QueryLoreVectorDB`, `UpdateQuestState`, `TriggerLevelSequence` |
| Character (NPC) | 페르소나·대사·감정 | `GetNPCMemory`, `SetFacialEmotion`, `SpeakTTS` |
| Rules (Resolution) | 메커니즘·검증·판정 | `RollDice`, `CheckInventory`, `ModifyPlayerHealth` |
| Interface (Mediator) | 멀티모달 입력·라우팅 | `GetPlayerGazeTarget`, `ParseGestureTag` |
