# SPEC: vr-grip-pose — 물체 쥐기·토크로 놓치기·손가락 그립 포즈

> 상태: **인터뷰 완료(2026-09-24)**. 근거: `docs/DESIGN_vr_physics_grip.md` + 손 트래킹 연구 노트.
> 선행: `SPEC_vr_ghost_hand.md`(물리 손, 핸드트래킹+컨트롤러 병행). 케이스 2(물리 그립) + 3(그립 비주얼)을 묶음.

## 목표

1. **물리 그립**: 물리 손이 물체를 constraint 로 쥔다. 모서리를 잡거나 한 손으로 큰 물체를 들면 토크 때문에 자연스럽게 놓친다.
2. **그립 비주얼**: 쥐는 동안 손가락이 물체를 감싼 모양이 된다.

## 범위 (변경 파일·시스템)

| 층 | 파일 | 변경 |
|---|---|---|
| C++ | `Core/BP/VRPawn.{h,cpp}` | 잡기 시 물리 손 ↔ 물체 사이 breakable `PhysicsConstraint` 생성·해제 |
| C++ | `Inventory/BP/ItemDataAsset.h` | `FItemData` 에 그립 필드 추가: 형상 유형, break 임계 오버라이드 |
| 에셋 | 손 AnimBP | 열린 손 ↔ 유형별 그립 포즈 블렌드(컨트롤러 입력일 때) |
| 에셋 | 잡을 수 있는 아이템 | 그립 소켓, Convex Decomposition(에셋당 Hull 10~20개 예산) |

## 결정 사항

- **토크 계산은 엔진에 맡김**: 무게중심 대비 그립 지점 토크는 Chaos 가 형상과 무관하게 계산한다. constraint 가 break 임계를 넘으면 놓친다. 직접 토크 계산 없음.
- **break 임계 = 전역 기본값 + 물체별 오버라이드**: 대부분 기본값, 무겁거나 특수한 아이템만 `FItemData` 에서 개별 지정.
- **양손 그립**: 두 손이 무게중심 양쪽을 잡으면 토크가 상쇄돼 안정. constraint 2개로 나오는 결과, 별도 코드 없음.
- **그립 데이터 위치 = `FItemData` 확장**: 아이템 정의 한 곳에서 관리. 인벤토리 아이템만 대상.
- **입력별 손가락 처리**:
  - **컨트롤러**: 형상 유형별 고정 포즈로 블렌드. 유형 4~5종(막대·박스·구·핀치 등). Control Rig 에 내장 wrap 솔버가 없어서 실시간 절차적 wrap 은 하지 않는다.
  - **핸드트래킹**: 포즈를 덮어쓰지 않는다. `SPEC_vr_ghost_hand.md` 의 물리 손가락 캡슐이 물체 표면에 막히는 결과를 그대로 쓴다.

## 완료 기준

- 작은 물체를 한 손으로 쥐고 흔들어도 안정(컨트롤러·핸드트래킹 각각).
- 긴 막대를 끝부분 한 손으로 들면 놓친다. 가운데를 잡거나 양손으로 들면 유지된다.
- 컨트롤러: 쥘 때 손가락이 유형별 그립 포즈로 전환된다.
- 핸드트래킹: 쥔 동안 손가락이 물체를 크게 관통하지 않는다.
- 기존 `InventoryComponent` 잡기·던지기 회귀 없음.

## 단계

- **M1**: breakable constraint 그립 + 놓침. `FItemData` 필드 추가.
- **M2**: 컨트롤러용 유형별 그립 포즈 4~5종 + 가장 가까운 그립 소켓 선택.
- **M3**: 핸드트래킹 물리 손가락 그립 안정화(PIE 튜닝).

## 미결 사항

1. **[리스크] 핸드트래킹 물리 손가락 그립 안정성.** 손가락 캡슐이 물체와 접촉한 채 Drive 로 계속 파고들면 떨림(jitter)이 생길 수 있다. 계산으로 확답 불가, M3 PIE 로 판정. 실패 시 대안: 핸드트래킹도 유형별 포즈로 덮어쓰기(Meta HandGrabPose 방식).
2. **가구 등 인벤토리 밖 물체는 범위 밖.** `FItemData` 만 확장하므로 월드 물체(가구·조각상)를 잡으려면 별도 데이터가 필요하다. 필요해지면 결정.
3. break 임계 전역 기본값: PIE 튜닝.
4. 형상 유형 목록 확정(막대·박스·구·핀치 외 추가 여부).
