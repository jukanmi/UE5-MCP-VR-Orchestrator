# SPEC: pause_settings — 메뉴(일시정지)·설정 UI

> 상태: 인터뷰 완료(2026-10-04), 미결 결정 2026-10-05. M0 ✅ · M1 ✅ 구현(헤드셋 없는 PIE 확인) · M2 ✅ 구현(헤드셋 없는 PIE 확인). 헤드셋 확인 대기 = DoList 2-8. M3(정보 화면: 지도·파티·퀘스트 로그) ✅ 구현(2026-10-06, 헤드셋 없는 PIE 확인). **헤드셋 확인 완료(DoList 2-8 전부 체크) — 완료, `docs/done/` 이관(2026-10-08).** Develop 머지는 별도.
> 연계: `SPEC_body_measure_prone.md` — 신체 측정 캘리브레이션의 진입점이 이 설정 UI 다. 설정 UI 가 먼저 있어야 그 M2 를 할 수 있다.

## 배경

게임에 일시정지·설정 화면이 없다. 설정으로 조절할 값(소리, 캘리브레이션)이 생기는데 둘 곳이 없다. 지금 있는 UI 는 손 패널(HUD)·인벤토리 패널·채팅 패널뿐이고, 입력 매핑(`IMC_VR`)에서 왼손 Menu 버튼은 비어 있다(왼손 Y = 인벤토리).

## 목표

1. **메뉴 열기·닫기**: 왼손 Menu 버튼으로 메뉴(재개·설정)를 띄우고 닫는다.
2. **설정 화면**: 첫 버전 항목은 신체 측정 캘리브레이션 진입, 사운드 볼륨. 값은 로컬에 저장돼 다음 실행부터 자동 적용.
3. 메뉴는 월드 UI 규약(`UWorldUIComponent` 상속, 양면·카메라 정렬)을 따르고, 손 컨트롤러·핸드트래킹 포인터로 누른다.

## 범위 (변경 파일·시스템)

| 층 | 대상 | 변경 |
|---|---|---|
| C++ | `UI/Components/` 메뉴 패널 컴포넌트(가칭 `UMenuPanelUIComponent`) | `UWorldUIComponent` 상속. 열림·닫힘, 포인터 입력, 항목 화면 전환(메뉴 ↔ 설정) |
| C++ | 설정 저장(가칭 `USettingsSaveGame` 또는 게임 사용자 설정) | 사운드 볼륨·캘리브레이션 결과 저장·읽기, 시작 때 적용 |
| C++ | `Core/BP/VRPawn` | 입력 바인딩(왼손 Menu 버튼). 폰에 로직을 더 쌓지 않고 `VRPlayerUIComponent` 쪽에서 받는 방향 |
| 에셋 | `IA_Menu`·`IMC_VR`, 메뉴·설정 위젯 BP, 사운드 클래스·믹스 | 입력 액션 신설, 위젯 트리(MCP 로 가능), 볼륨 조절용 사운드 클래스 |

## 결정 사항

- **일시정지는 월드를 멈추지 않는다.** 모든 게 계속 흐르고 메뉴만 띄운다. VR 에서 월드·폰을 멈추면 시야가 굳어 멀미가 나고, 서버 LLM 응답과 NPC 흐름이 계속되는 구조와도 충돌하기 때문이다. 그래서 이름도 "일시정지"가 아니라 "메뉴"로 취급한다.
- **진입**: 왼손 Menu 버튼 토글. 손 패널 버튼은 이번에 만들지 않는다.
- **첫 버전 설정 항목**: 신체 측정 캘리브레이션, 사운드 볼륨. 이동·회전(스무스·스냅 턴·비네트), 손·입력 튜닝은 뺀다.
- **저장**: 로컬 저장, 다음 실행부터 자동 적용.
- **나가기**: 메뉴에는 재개·설정만 둔다. 게임 종료·메인 메뉴는 만들지 않는다(메인 메뉴가 아직 없다).

## 완료 기준 (헤드셋)

- [ ] 왼손 Menu 버튼으로 메뉴가 눈앞에 뜨고, 다시 누르면 닫힌다. 월드·NPC 는 계속 움직이고 시야·손 추적이 멈추지 않는다.
- [ ] 손(컨트롤러·핸드트래킹)으로 재개·설정 항목을 누를 수 있고 인벤토리·손 패널과 겹치거나 가리지 않는다.
- [ ] 설정에서 사운드 볼륨을 바꾸면 즉시 소리가 바뀌고, 게임을 껐다 켜도 유지된다.
- [ ] 설정에서 신체 측정 캘리브레이션 항목으로 들어갈 수 있다(측정 자체는 `SPEC_body_measure_prone` M2).

## 추가 결정 (2026-10-05)

- **저장 = `USaveGame` 슬롯** 하나(`USettingsSaveGame`). 볼륨·신체 측정 결과를 같은 슬롯에 둔다. 시작 때 읽어 적용.
- **메뉴가 열린 동안 이동·스냅턴·공격·잡기 입력을 막는다.** 놓기·메뉴 닫기·포인터는 허용하고, 쥔 물건은 놓지 않고 유지한다.
- **위치 = 열 때 눈앞 월드 고정.** 여는 순간 시선 앞 약 1m 에 놓고 그 자리에 고정, 카메라를 향해 회전만 한다. 열 때마다 위치를 갱신한다. 시야·머리를 따라오지 않는다(멀미).
- **볼륨 = 마스터 서브믹스 출력 볼륨**(`SetSubmixOutputVolume`) 하나. 새 에셋 없이 모든 소리에 일괄 적용. 배경·효과·대사 분리는 첫 버전 밖.

## M3 — 메뉴 정보 화면 (인터뷰 2026-10-06, 구현 2026-10-06)

메뉴를 설정 위주가 아니라 "지금 상황을 보는 곳"으로 확장한다. 개발자 옵션·단순 온오프는 넣지 않는다. 월드가 멈추지 않는 메뉴라 지도·파티 확인에 잘 맞는다.

**결정**
- **구성:** 메뉴에 탭 구조를 둔다(메인 / 지도 / 파티 / 퀘스트 / 설정). 화면은 하나씩 붙인다. 관계(호감도) 화면은 이번에 넣지 않는다.
- **지도 = 정적 탑다운 이미지 + 마커.** 개발 중 `SceneCapture` 로 한 번 촬영해 텍스처 에셋으로 두고, 위젯 위에 위치 점만 얹는다. 런타임 렌더 비용이 0 이라 Quest 에 맞다. 맵(500m)이 바뀌면 다시 촬영한다. 월드 좌표 → 이미지 좌표 변환은 촬영 범위(원점·크기)를 상수로 고정해 쓴다.
- **지도 표시 범위 = 플레이어·일행·퀘스트 목표만.** 모든 NPC·구역을 드러내지 않아 탐험 재미를 지킨다. 목표는 `UStorySubsystem` 이 마커에 쓰는 대상과 같은 것(`quest_target_tag`)이다. 서브퀘스트 목표는 목표 마커 SPEC(별도)이 정해지면 같이 붙인다.
- **파티 화면 = 목업 데이터.** 일행 목록·상태(HP)를 보여 주되 `SPEC_party` 의 `UPartySubsystem` 이 아직 없으므로 데이터 소스를 목업으로 둔다. 화면은 "일행 뷰 목록"(AgentID·표시명·HP 비율)만 읽고, 그 목록을 만드는 곳(소스)만 목업이다 — 임시로 레벨의 아군 NPC(Elara·James·Skadi·Moca·Guard 중 고정 N명)를 일행으로 보고 HP 는 실제 NPC 스탯을 읽는다. `UPartySubsystem` 이 생기면 소스만 교체하고 화면 계약은 바꾸지 않는다(POI 태그 목업 → 실제 시스템 교체와 같은 방식).
- **퀘스트 로그:** 현재 메인 목표(`quest_log`)와 활성·가능 서브퀘스트 목록. 서브퀘스트를 받았는데 안내가 없던 문제(2026-10-05)를 보완한다.

**완료 기준(헤드셋)**
- [ ] 메뉴에서 탭을 오가며 지도·파티·퀘스트 화면을 볼 수 있고 포인터로 탭이 눌린다.
- [ ] 지도에 플레이어 위치·방향이 실제와 맞게 찍히고, 퀘스트 목표 위치가 마커와 일치한다.
- [ ] 퀘스트 로그가 현재 목표·서브퀘스트와 일치한다(서버 `Story` 블록 기준).
- [ ] 파티 화면이 목업 일행(고정 N명)과 그들의 실제 HP 를 보여 주고, 일행이 없으면(목업 목록이 비면) "일행 없음"을 표시한다.

**구현 결과 (2026-10-06)**
- **화면 전환은 탭 막대가 아니라 메인 목록 방식**: 메인(재개·지도·파티·퀘스트·설정)에서 각 화면으로 들어가고 각 화면의 뒤로 버튼이 메인으로 돌아온다(`EMenuScreen`, 위젯이 전환만 하고 데이터는 `UVRPlayerUIComponent::UpdateMenuInfo` 가 밀어 넣는다). 패널 캔버스는 640×560.
- **지도**: `/Game/Core/interface/T_WorldMap`(2048², `SceneCapture2D` 직교·`SCS_BASE_COLOR` 로 `(0,0)` 중심 51000cm 를 한 번 촬영, `compression_no_alpha` — 알파 0 이라 안 끄면 반투명). 영역은 `NavMeshBoundsVolume`(중심 0,0 · 반경 25500)과 같다. 위에서 보면 위쪽 = 월드 +X, 오른쪽 = +Y(대성채 DemonLord(17500,14400)가 오른쪽 위에 찍히는 것으로 확인). 마커는 캔버스 앵커 비율(0~1)이라 픽셀 계산이 없다. 플레이어(흰색)+방향 점(하늘색), 퀘스트 목표(노란색, `UStorySubsystem::GetQuestTargetActor`), 일행(초록, 목업). 맵이 바뀌면 같은 설정으로 다시 촬영한다(`MapWorldCenter`·`MapWorldSize` 는 `PlayerUI` 프로퍼티).
- **파티**: 목업 `MockPartyIds`(Elara·James·Skadi) + 실제 NPC HP. `UPartySubsystem` 이 오면 소스만 교체.
- **퀘스트**: 서버 `Story` 블록에 서브퀘스트 표시명을 같이 싣게 했다(`side_titles` — `app/story/state.py`, 서버 테스트 갱신, UE `FStoryState::SideTitles`). 서버 응답이 없으면 "아직 받은 퀘스트 정보가 없습니다".
- **PIE 확인**: 지도(목표·일행·플레이어 점이 올바른 위치)·파티(3명 HP 100%)·퀘스트(서버 없음 문구) 화면. 서버 `Story` 블록이 있을 때의 퀘스트 글(서브퀘스트 제목)은 서버를 켜고 확인해야 한다.

**단계:** M3-a 탭 구조 · M3-b 퀘스트 로그 · M3-c 지도(촬영·변환·마커) · M3-d 파티 화면(목업 소스 — `SPEC_party` M1 이 오면 소스만 교체).

## 미결 사항

- **메뉴·인벤토리 패널이 겹칠 때 우선순위**(헤드셋 확인 후 정한다). 현재는 메뉴를 열 때 인벤토리를 닫고, 메뉴가 열린 동안 인벤토리 열기를 무시한다.
- **핸드트래킹에서 Menu 버튼**: 컨트롤러를 안 쥐면 Menu 버튼이 없다. 대체 입력(손목 필 제스처 등)은 이번에 안 만든다 — 필요하면 별도 결정.
- **시스템 메뉴(오큘러스 버튼)** 와의 충돌: 왼손 Menu 버튼이 OS 시스템 예약 입력과 겹치는지 헤드셋 확인(DoList 2-8).
- **서브믹스 볼륨이 Quest 에서 안 먹으면** 사운드 클래스 + 믹스 방식으로 교체(결정 번복).
- **신체 측정 진입**: 설정 화면의 "신체 측정" 버튼은 자리만 있다. `SPEC_body_measure_prone` M2 가 연결한다.
- **지도 촬영 범위·해상도**와 월드 → 이미지 좌표 상수(M3-c). 지도가 월드 파티션 레벨에서 한 번에 촬영되는지.
- **지도에 일행 위치를 보이는 경우** 일행이 플레이어 근처에 모여 있으면 점이 겹친다 — 표시 규칙은 목업 일행으로 먼저 보고 정한다.
- **목업 일행의 고정 인원**(N)과 어떤 NPC 를 고를지. `UPartySubsystem` 이 오면 목업 소스를 지운다(남기지 않는다).
