# SPEC: vr-grip-pose — 손으로 물체 밀기·들기·손가락 그립 포즈

> 상태: **M0~M4 완료(2026-09-30, 헤드셋 확인)** — 충돌·토크·마찰은 언리얼 내장 Chaos. 들어올리기 = A(끊어지는 PhysicsConstraint). 쥐기 = 접촉(핀치·주먹). 손가락 = 가운데·끝마디 캡슐 + 관절별 고정. 남은 것: 컨트롤러 감싸기(듀얼 입력과 함께)·물건별 끊김 임계.
> 개정(2026-10-03): 쥔 물건의 마찰·회전 한도와 양손 쥐기는 `SPEC_friction_grip.md` 로 이어 간다 — 아래 "마찰 직접 계산 안 함" 결정은 쥐기 제약 상한에 한해 뒤집힌다.
> 이전: 인터뷰 완료(2026-09-24), 근거 `docs/DESIGN_vr_physics_grip.md` + 손 트래킹 연구 노트.
> 선행: `SPEC_vr_ghost_hand.md`(물리 손바닥·손끝 캡슐, 핸드트래킹+컨트롤러 병행).

## 방향 수정 이유

고스트 핸드(M3)에서 손끝이 막히는 처리를 로직(손바닥 목표 되돌리기)으로 짰을 때는 박힘과 되돌림이 반복돼 떨렸다.
손끝 캡슐을 손바닥 바디에 용접해 Chaos 충돌에 맡기자 표면에서 안정적으로 멈췄다(헤드셋 확인).
아이템도 같은 방식으로 한다. 직접 계산하는 접촉·토크·마찰 로직은 만들지 않는다.

## 목표

1. **접촉**: 손(손바닥 상자·손끝 캡슐)과 아이템이 Chaos 로 직접 충돌한다. 손으로 밀고, 받치고, 쳐낼 수 있다. 무거운 물체는 손이 못 밀고 표면에서 막힌다.
2. **들어올리기**: 쥐는 동작으로 아이템을 든다. 방식은 미결(아래 후보). 내장 기능 중에서 고른다.
3. **그립 비주얼**: 쥐는 동안 손가락이 물체 표면에서 멈춰 감싼 모양이 된다.

## 결정 사항

- **충돌·토크·마찰은 Chaos 내장**: 접촉 해결, 무게중심 대비 토크, 마찰로 미끄러짐까지 엔진이 계산한다. 직접 계산하는 로직 없음.
- **손과 아이템은 같은 충돌 규칙**: 손 채널(HandLeft/HandRight)은 벽과 같이 아이템(PhysicsBody)도 막는다. 아이템 쪽은 새 채널 기본 응답이 Block 이라 추가 설정이 없다.
  고스트 핸드 M1 에서 손이 PhysicsBody 를 무시하게 한 이유("쥐려고 손을 뻗으면 아이템을 밀쳐 냄")는 이번에 되살아나므로, 잡기 판정 반경(`GrabRadius`)이 접촉 전에 걸리는지 PIE 로 확인한다.
- **밀 수 있는 무게 = 손 드라이브 최대 힘 × 아이템 질량**: 별도 임계 없이 `HandDriveMaxForce` 와 아이템 질량으로 결정된다.
- **놓기 분기는 유지**: 그립 홀드 입력(`Started` 쥠 / `Completed`·`Canceled` 놓음)과 놓을 때 분기(인벤토리 열림 = 회수 / 닫힘 = 거래접시 → NPC 건네기 → 던지기)는 그대로 둔다. 부착 방식을 바꾸면 `.agents/rules/pitfalls.md` C 의 "손 쥐기 규칙(사용자 지정 2026-09-07)" 을 같이 갱신한다.
- **들어올리기 = A(끊어지는 PhysicsConstraint)** (M2): 손 바디 ↔ 아이템 이동·회전 잠금 제약, 힘·토크 임계 넘으면 끊겨 놓침. 쥐는 동안 손 드라이브에 쥔 물건 질량 배율.
- **그립 비주얼 = 닿을 때까지 굽히기** (M3, 2026-09-29 변경 — 이전: 컨트롤러용 형상 유형별 고정 포즈):
  - 쥐기 제약이 손 ↔ 쥔 물건 충돌을 꺼 두므로 Chaos 로는 손가락이 멈추지 않는다(헤드셋 확인: 쥐어지지만 손가락이 물건을 뚫음).
  - 손가락마다 관절 굽힘을 0(편 손가락)~1(트래킹 그대로) 비율로 줄여, 끝마디 캡슐이 쥔 물건과 겹치지 않는 가장 큰 비율을 쓴다(이분 탐색, 겹침 판정 = `OverlapComponent`).
  - 고정 포즈·형상 분류가 필요 없어 어떤 물건 모양에도 맞는다.
  - **핸드트래킹**: 위 방식. 쥔 물건 외 표면은 지금처럼 손끝 캡슐의 Chaos 접촉.
  - **컨트롤러**: 보류 — 컨트롤러일 땐 손가락 관절 데이터가 없고 손끝 모양 충돌도 꺼져 있다. 듀얼 입력(한 손 컨트롤러·한 손 트래킹)과 함께 다룬다. 방식은 같다(편 손 → 주먹 목표로 굽히다 닿으면 멈춤).

## 들어올리기 후보 (결정: A — 모두 엔진 내장)

| 후보 | 방식 | 장점 | 단점 |
|---|---|---|---|
| A. 끊어지는 PhysicsConstraint | 쥐는 순간 손 바디 ↔ 아이템 사이 제약 생성, 힘·토크 임계 넘으면 끊김 | 원래 계획. 긴 막대 끝을 한 손으로 들면 토크로 놓침, 양손이면 유지 — 토크를 엔진이 계산 | 끊김 임계 튜닝 필요 |
| B. UPhysicsHandleComponent | 아이템을 목표 위치로 끄는 내장 핸들 | 구현 짧고 부드러움 | 토크로 놓치는 표현이 약함, 손가락 접촉과 따로 논다 |
| C. 마찰만(손가락 압착) | 제약 없이 손끝 캡슐이 물체를 눌러 마찰로 든다 | 가장 물리적 | VR 트래킹 노이즈로 미끄러짐·떨림이 흔함 — 단독 사용은 비현실적 |
| D. 소켓 스냅 유지 | 들 때만 지금처럼 손에 붙이고, 접촉만 Chaos | 이미 동작, 놓기 분기 그대로 | 들고 있는 동안 물리 없음(토크 놓침 없음) |

결정 기준: 헤드셋에서 "작은 물체 안정 + 긴 막대 끝 놓침"을 보여 주는지. M1 접촉 확인 뒤 A 로 결정(2026-09-27).

C 헤드셋 실험(2026-09-30, 폐기): 손 마찰 2.0 으로 0.5kg 양동이는 들렸으나 떨림. 2.5kg 은 손 드라이브가 손바닥 질량(0.73kg) 기준이라 처져 못 듦.
결정적 단점 — 쥔 물건이 인벤토리에 등록되지 않아 아이템 사용 키·놓기 분기(거래접시·NPC 건네기·던지기)를 못 쓴다. A 유지.

## 완료 기준

- 손(핸드트래킹·컨트롤러)으로 테이블 위 아이템을 밀고, 받치고, 쳐낼 수 있다. 무거운 아이템은 손이 표면에서 막힌다.
- 핸드트래킹 핀치·주먹으로 손 근처 아이템을 잡는다(컨트롤러 그립과 동일).
- (들어올리기 결정 후) 작은 물체를 한 손으로 들고 흔들어도 안정. A 채택 시: 긴 막대 끝을 한 손으로 들면 놓치고, 가운데·양손이면 유지.
- 핸드트래킹: 쥔 물건을 감싸면 손끝이 표면에서 멈추고 물건 안으로 들어가지 않는다. 손을 펴면 다시 트래킹을 따른다.
- 놓을 때 분기(회수 / 거래접시 / NPC 건네기 / 던지기)와 던지기 손 속도·투척 데미지가 그대로 동작한다.

## 단계

- **M0 (선행)**: 잡기 판정 위치·손 속도를 트래킹 앵커 기준으로 — 핸드트래킹 핀치·주먹 잡기가 실제로 손 근처 아이템을 잡게.
- **M1**: 손 ↔ 아이템 Chaos 접촉(손 채널 PhysicsBody Block, 아이템 단순 콜리전 점검). 헤드셋으로 밀기·받치기·쳐내기 확인.
- **M2** ✅: 들어올리기 A — 끊어지는 PhysicsConstraint(헤드셋에서 쥐어짐 확인).
- **M3** ✅: 닿을 때까지 굽히기(핸드트래킹) + 접촉 쥐기(엄지와 다른 손끝 사이에 물건이 끼면 쥠, 충돌 유지). 컨트롤러 감싸기는 듀얼 입력과 함께.
- **M4** ✅: 가운데 마디 콜라이더 + 관절별 고정 감싸기 + 주먹 쥐기 판정(아래 M4 절).

## M4 — 가운데 마디 콜라이더·주먹 쥐기 (2026-09-30 완료, 헤드셋 확인)

**문제(헤드셋 확인)**: ① 주먹으로 감싸 쥐면 엄지가 물건이 아니라 손가락 위를 덮어 접촉 쥐기(엄지 + 다른 손끝)가 안 걸린다.
② 굵은 물건을 감싸면 가운데 마디가 물건에 파고든다 — 끝마디 캡슐만 있고, 감싸기도 끝마디만 검사한다.

**범위**

| 층 | 파일 | 변경 |
|---|---|---|
| C++ | `Core/BP/VRPawnAnimInstance.{h,cpp}` | 손가락 모양을 끝마디 5개 → 가운데 마디 포함 10개로(메시 정점에 맞춤, 엄지는 첫 마디가 가운데). 손바닥 기준 목표도 마디별 |
| C++ | 〃 | 감싸기 = **관절별 고정**(쥔 물건만이 아니라 손 근처 20cm 아이템 전부): 가운데 마디가 닿으면 첫째·둘째 관절, 끝마디가 닿으면 세 관절을 직전 프레임(안 닿았던) 각도에 고정 — 안 고정된 끝 관절은 계속 굽어 감싼다. 실제 손가락이 고정 각도보다 5° 넘게 펴지면 풀고, 근처에 물체가 없으면 모두 푼다. (처음 계획한 매 프레임 이분 탐색은 대체 — 쥐기 전 닿은 물체에서 캡슐이 트래킹대로 물체 속에 옮겨져 손 전체가 밀렸다 당겨지며 떨렸다) |
| C++ | `Core/BP/VRPawn.{h,cpp}` | 손끝 캡슐 배열 → 손가락 캡슐 배열(손당 10개, 손바닥에 용접). 크기·배치·충돌 켜기 로직을 마디 공통으로 |
| C++ | 〃 | 접촉 쥐기 판정에 **주먹 쥐기** 추가 — 손바닥 모양이 물건에 닿고, 손가락 2개 이상(어느 마디든)이 같은 물건에 닿고, 손바닥 중심→그 마디를 잇는 선이 물건을 지나면 쥔다. 놓기 = 손바닥 또는 모든 손가락이 1.5cm 넘게 떨어짐 |

**결정**

- **가운데 마디만** — 첫 마디(손가락 뿌리)는 손바닥 상자와 겹쳐 효과가 적다. 파고듦은 대부분 가운데 마디에서 생긴다.
- **엄지 규칙 유지** — 핀치(엄지 + 다른 손가락)는 그대로, 주먹 규칙은 추가. 둘 중 하나만 맞으면 쥔다.
- **손↔물건 충돌은 끄지 않는다**(사용자 지정) — 떨림은 캡슐이 물체 속으로 순간이동하지 않게(관절 고정) 해서 없앤다.
- **밀기 오판 방지는 같은 원리** — 손을 편 채 밀면 손바닥 중심→손끝 선이 물건 표면 위로 지나가 걸리지 않는다.

**성능 측정** — 캡슐을 옮길 때마다 손 바디에 다시 붙인다(재용접). 캡슐이 늘면 쥐었다 폈다 할 때 비용이 늘 수 있어,
추가 전후 PIE `stat physics` 로 프레임당 물리 시간을 비교한다. 크게 늘면 재용접 임계(0.2cm·2°)를 키우거나 쥔 동안은 마디 캡슐 이동을 멈춘다.

**결과** — 물리 시간 프레임당 약 0.5ms(`stat physics`, 90Hz 예산 11ms 의 5%). 떨림은 계산량이 아니라 쥐기 전 닿은 물체에서 캡슐이 트래킹대로 물체 속에 옮겨지던 것이 원인이었고 관절별 고정으로 해소. 툭 치면 굳는 문제는 "실제 손가락 모양이 안 겹치면 풀기"로 해소.

**완료 기준**

- 주먹으로 양동이 손잡이·막대를 감싸 쥐면 쥐어지고, 손가락을 펴면 놓인다.
- 굵은 물건을 감싸면 가운데 마디도 표면에서 멈추고 끝마디가 마저 감싼다.
- 손을 편 채 밀면 쥐어지지 않는다(M1 밀기 회귀 없음). 핀치 쥐기 회귀 없음.
- `stat physics` 가 추가 전 대비 눈에 띄게 늘지 않는다(측정값 기록).
