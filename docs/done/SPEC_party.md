# SPEC: party — 파티(일행) 멤버십

> 인터뷰 결정 2026-10-06, 미결 4건 확정 2026-10-08(D6~D9). 의도·결정만 적는다(구현 세부는 코드가 설명). 상태: ✅ M1~M3 구현(2026-10-08, `verify all` 통과). 헤드셋 없는 PIE 확인: 디버그 명령(`/api/npc/Guard/command`)으로 JoinParty → 합류(1/4)·서버 일행 동기·플레이어 추적(15m 이동 후 1.9m)·Jev 일상 억제, Stop → 해산(0/4)·서버 동기·일상 복귀. 미확인: 전투 후 추적 재개, LLM 경유 합류·거절(아래 미결).

## 배경

시나리오(`STORY_SCENARIO.md` 2막 "동료 규합", `b3_recruit_party`)는 NPC 를 "파티에 영입"한다고 쓰지만 코드에는 파티가 없다. 스토리는 `talked_to` 대화 횟수로 비트를 넘길 뿐 누가 일행인지 어디에도 저장하지 않고, 아군 NPC 는 매번 호감도·시야로 우호·적대를 따로 판정한다.
2026-10-05 헤드셋 테스트에서 이 빈틈이 두 가지로 드러났다.
- "따라와"(`Follow`)가 한 번 이동하고 끝났다 → 지속 추적으로 고쳤지만(`2e236262`), 전투가 끼면 추적이 끊기고 복구되지 않는다.
- 아군끼리 피격이 누적돼 호감도가 깎여 서로 싸웠다(`Guard→James -20` 등). 일행이라는 개념이 없어 아군 오사를 구분하지 못한다.

## 목표

**누가 플레이어의 일행인지를 한 곳이 소유**하고, 그 상태를 서버(LLM·디렉터)가 알며, 일행은 플레이어를 따라다니되 반응(대화·반사·전투)은 유지한다. 합류·해산은 대화(LLM)로 일어난다.

범위 밖(이번 SPEC 에서 다루지 않음): 대형(플레이어 뒤 슬롯 배치), 전투 연계(타겟 공유·후퇴), 스토리 비트 자동 합류, 파티 UI·제스처 명령, 파티 저장/불러오기.

## 결정 사항

**D1. 멤버십 상태만 이번 범위.** 누가 일행인지·최대 인원·합류/해산이 전부다. 대형·전투 연계·스토리 자동 합류는 후속.

**D2. 정본 = C++ `UPartySubsystem`.** 액터·`NPCManager` 와 같은 층에서 소유한다. 변경될 때마다 서버에 `party_update` Envelope 로 알려 프롬프트·디렉터가 읽는다. 서버가 없어도(오프라인) 파티는 동작한다.

**D3. 합류·해산은 대화(LLM) + 호감도 조건.** 플레이어가 "같이 가자"고 하면 NPC 가 `JoinParty` 로 수락하거나 거절한다. 호감도·스토리 진행이 조건이고, **서버가 조건을 판정**해서 충족할 때만 `JoinParty` 를 낼 수 있게 한다(호감도는 서버 DB 가 정본). "조작 기능 임의 추가 금지" 규칙과 충돌 없음(대화로만).

**D4. 일행의 행동 = 따라다니되 반응은 유지.** 합류하면 플레이어를 지속 추적(`Follow`)한다. 일상 활동(wander 등)만 끄고, 대화·척수반사·전투 반응은 그대로 둔다. 전투가 끝나면 다시 따라붙는다(현재는 전투 종료 뒤 추적이 복구되지 않는 빈틈 — 이 SPEC 에서 메운다).

**D5. 해산 = `LeaveParty` 또는 `Stop`.** 해산하면 추적을 풀고 일상 활동을 되돌린다. 일행이 죽으면 자동 제거한다.

**D6. 최대 인원 = 4명.** 아군 SmartNPC 5명 중 4명까지. 다 찬 상태의 `JoinParty` 는 C++ 가 거절한다(서버 판정과 별개의 최종 가드).

**D7. 합류 조건 = 호감도만.** 서버가 NPC→플레이어 호감도가 임계 이상일 때만 `JoinParty` 를 허용한다. 임계값은 PIE 에서 정한다(초안 +20). 스토리 비트 연동은 후속 SPEC.

**D8. 파티원끼리의 피격은 호감도를 깎지 않는다.** 서버 `_apply_hostile_affinity` 가 가해자·피해자가 모두 파티원이면 -5 를 건너뛴다. 아군이 서로 때리는 근본 원인 조사는 별도.

**D9. `party_update` = 증분.** 합류·해산 한 건마다 `{agent_id, change: join|leave}` 로 보낸다. 증분이라 서버 재시작·재연결 때 상태가 어긋날 수 있으므로, C++ 는 WebSocket 재연결 직후 현재 멤버 전원을 `join` 으로 다시 보낸다(서버는 `join` 을 멱등으로 처리).

## 완료 기준

- **M1** PIE 에서 `JoinParty` 액션을 주면 멤버 목록에 들어가고 `party_update` 가 서버로 가며, 서버 프롬프트에 현재 일행이 보인다. 최대 인원을 넘으면 거절된다. `LeaveParty`·사망 시 목록에서 빠진다.
- **M2** 합류한 NPC 가 플레이어를 지속 추적하고 일상 활동을 시작하지 않는다. 적을 만나 전투에 들어갔다가 끝나면 다시 플레이어를 따라온다. 해산하면 추적이 풀리고 일상 활동이 돌아온다.
- **M3** 호감도·스토리 조건을 서버가 판정해 조건 미달이면 NPC 가 거절하는 대사를 한다. 같은 일행이 둘 다 파티에 있을 때 LLM 프롬프트가 "누가 일행인지"를 정확히 안다.
- 모든 마일스톤: `sol_pi verify all` 통과. 헤드셋 확인은 DoList 에 등록.
