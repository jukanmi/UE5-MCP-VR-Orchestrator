# SPEC: rubik_cube

작성 2026-10-09 (인터뷰 완료), 2026-10-10 입력 방식 개정(손가락 밀기 → 양손 비틀기 물리). 브랜치: 구현 착수 시 `Develop` 에서 `feature/rubik-cube` 분기.

## 목표
VR 에서 **양손으로 쥐고 비틀어** 층을 돌리는 **2x2 큐브**(장난감). 한 손이 큐브를 쥐고, 다른 손이 반대쪽 절반을 쥐고 손목을 비틀면 그 토크로 층이 물리적으로 돈다. 회전은 "조건을 만족하면 실행"이 아니라 손의 움직임에 따라 연속적으로 일어난다.
섞기·보상·인벤토리 연동은 범위 밖 — 완성 시 델리게이트만 낸다.

## 범위 (변경 파일·시스템)
- 신규 `Source/UE5_MCP_VR/Inventory/BP/RubikCube.{h,cpp}` — `ARubikCube : ADroppedItemBase`. 한 손 쥐기·던지기·놓기는 `ADroppedItemBase` 그대로 쓴다.
- 수정 `Inventory/BP/DroppedItemBase.{h,cpp}` — 쥘 대상 바디를 고르는 가상 함수 1개(기본 구현은 `ItemMesh` 반환).
- 수정 `Player/Components/VRHandComponent.cpp` — `GrabConstraint->SetConstrainedComponents` 대상을 위 가상 함수 결과로 바꾸는 한 곳.
- 에셋 없음. 큐비·스티커는 엔진 기본 도형(`/Engine/BasicShapes/Cube`, `Plane`)으로 코드가 만든다.
- 건드리지 않는 것: Python 서버·Envelope(큐브는 UE 안에서만 완결), `DT_ItemRegistry`, 인벤토리.

## 결정 사항
1. **입력은 양손 비틀기**. 손A 가 큐브를 쥔 상태에서 손B 가 큐브를 쥐면 손B 는 큐브 전체가 아니라 **층 바디**를 쥔다. 손B 의 그립 드라이브(기존 `GrabConstraint`) 토크가 층을 돌린다. 컨트롤러·핸드트래킹 모두 기존 쥐기 경로를 그대로 탄다.
   - 두 손이 같은 바디를 쥐면 비틀림 토크가 한 강체 안에서 상쇄되므로, 층은 반드시 별도 시뮬레이션 바디여야 한다.
   - 한 손가락으로 밀거나 튕겨 돌리기는 범위 밖.
2. **2x2 고정**. 큐비 8개를 `±1` 정수 격자 좌표로 관리한다. N×N 일반화는 하지 않는다(3x3 은 이 SPEC 이후 별도 판단).
3. **레벨 배치 전용 아이템**. `ADroppedItemBase` 를 상속하지만 레지스트리 행이 없다 → 쥐기·던지기·놓기는 되고 인벤토리 수납·거래는 안 된다(수납 실패 시 그 자리 드랍). 질량·한 변 크기(기본 8cm)는 `ARubikCube` 가 직접 정한다. 손↔큐브 충돌은 끄지 않는다.
4. **비주얼은 코드 생성**. 큐비 8개(검은 몸체, 사이 틈 약간) + 바깥 면 스티커 24장(6색 고정 팔레트). 큐비·스티커 메시는 충돌 없음. 충돌은 평소엔 큐브 전체 박스(`ItemMesh`) 하나, 층이 분리된 동안엔 코어 절반 박스 + 층 절반 박스 두 개.
5. **물리 구조 (층 분리 중)**
   ```
   손A GrabConstraint ──▶ 코어 바디(ItemMesh, 나머지 큐비 4개)
                               │ 힌지 PhysicsConstraint (그때 고른 회전축 1개만 Free, 나머지 Locked, 코어↔층 충돌 끔)
   손B GrabConstraint ──▶ 층 바디(큐비 4개)
   ```
   - 큐브의 회전축은 로컬 주축 3개(X·Y·Z)이고 셋 다 돌 수 있다. 다만 실제 큐브 기구처럼 **동시에 도는 축은 하나**라, 힌지는 미리 3개를 만들어 두지 않고 쥐는 순간 고른 축으로 1개만 만든다. 층 구성원(어느 큐비가 그 층인지)은 회전할 때마다 바뀌므로 고정 힌지로는 표현할 수 없다.
   - 층은 "축 + 절단면"으로 정한다. 2x2 는 축마다 절단면 1개(중심) → 3축 × 1 = 절단면 3개, 축마다 돌 수 있는 쪽 2개. 3x3 으로 가면 축마다 절단면 2개(±1/3) → 3축 × 2 = 6개, 축마다 회전 메시(층 바디) 후보가 2개가 된다. 2x2 구현에서도 층 선택을 이 형태(축, 절단면 오프셋)로 표현해 3x3 확장 시 절단면 목록만 늘리면 되게 한다.
   - 힌지가 축 성분 토크만 통과시킨다. 반작용은 힌지를 거쳐 코어로 가고 손A 그립 토크가 버틴다. 돌리는 토크가 손A 그립 토크 한계(`ComputeGrip`)를 넘으면 큐브가 손 안에서 미끄러진다 — 별도 처리 없음.
   - 층 바디 질량·관성은 큐브 질량의 절반으로 둔다. 힌지 드라이브 강성·감쇠는 그립 드라이브처럼 관성 × ω² · 임계감쇠로 정한다.
6. **층 선택은 손B 가 쥐는 순간 한 번만** (회전 판정이 아니라 쥘 때의 기하 판정).
   - 회전축 `a` = 큐브 로컬 주축 중 (손A 쥔 점 → 손B 쥔 점) 방향과 가장 평행한 축.
   - 층 = 축 `a` 의 절단면 중 손A·손B 쥔 점 사이에 있는 면 기준으로 손B 쪽(2x2 는 절단면이 중심 하나뿐이라 손B 쪽 절반, 큐비 4개).
   - 층이 이미 분리돼 정착 중이면(아래 7) 그 층을 그대로 쥔다. 다른 축 층은 정착이 끝나야 쥘 수 있다(한 번에 한 층).
7. **스냅 코드 없음 — 디텐트로 정착**. 힌지 각도 드라이브 목표를 현재 각도에서 가장 가까운 90° 배수로 매 틱 갱신하는 약한 스프링(스피드큐브 자석 느낌) + 감쇠. 손B 가 놓으면 감쇠되며 자리를 잡고, 세게 비틀면 관성으로 다음 90° 를 넘어간다.
8. **정착 시 정수 상태로 확정**. 손B 가 놓은 상태에서 각도 오차 1° 미만 + 각속도 ≈ 0 이 되면: 층 큐비 좌표를 `±1` 로 반올림, 회전을 축 정렬 쿼터니언으로 반올림 → 층 큐비를 코어로 재합침, 힌지·층 바디 제거, `ItemMesh` 충돌을 전체 박스로 복구. 부동소수 누적 오차는 이 시점에 매번 0 으로 돌아간다.
9. **완성 판정은 논리 상태만**. 큐브 로컬 6방향 각각에 보이는 스티커 색이 모두 같으면 완성(큐브를 통째로 돌려도 무관). 8 의 확정 때마다 검사, 미완성→완성으로 바뀌는 순간 `OnSolved` 델리게이트 1회 + 로그.
10. **시작은 완성 상태. 섞기는 사용자가 손으로 직접** — `Scramble()`·치트 명령·흔들기 섞기는 만들지 않는다.

## 완료 기준
- [ ] 큐브를 한 손으로 쥐고 다른 손으로 6방향 어느 절반이든 쥐고 비틀면 층이 손을 따라 돌고, 놓으면 정확히 90° 배수에 선다(헤드셋 확인).
- [ ] 비트는 동안 다른 축 층은 돌지 않는다. 손A 그립보다 세게 비틀면 큐브가 손 안에서 미끄러질 뿐 터지거나 튀지 않는다.
- [ ] 임의 수순(양방향 각 10회) 뒤 큐비 좌표·회전이 격자 값에서 벗어나지 않는다(자동 확인 가능한 항목).
- [ ] 섞은 뒤 되돌리면 `OnSolved` 가 정확히 1회 발생, 처음 완성 상태로 시작할 땐 발생하지 않는다.
- [ ] C++ 변경이라 `python tools/sol_pi.py verify all` 통과. 클래스 추가라 Live Coding 불가 — 에디터 종료 후 빌드(MCP `quit_editor` → 빌드 → 재기동).

## 미결 사항 (작업 중 발견 시 추가)
- Chaos 안정성: 층 바디 약 50g, 손 드라이브 2개 + 힌지 사슬 → 떨림 가능. M0 에서 확인, 필요하면 서브스텝 또는 힌지 강성 조정.
- 두 손의 선형 드라이브가 힌지를 통해 서로 당긴다(손 사이 거리 변화) → 그립 힘 한계 안에서 미끄러지는지, 튀는지 확인.
- 손B 가 쥔 점이 큐브 중심 평면 근처(두 절반 경계)면 층 선택이 흔들릴 수 있음 → 필요하면 경계 근처 쥐기는 큐브 전체 쥐기로 처리.
- 디텐트 강도·정착 임계(1°)·큐브 크기(8cm)·질량은 초안값 — 헤드셋에서 조정.
- `BasicShapeMaterial` 의 색 파라미터 이름 확인 필요(없으면 단색 머티리얼 에셋 1개를 추가).
- 90° 디텐트 통과 시 햅틱 틱은 이번 범위에서 뺌 — 헤드셋 체감 뒤 판단.
- 3x3 확장 여부는 2x2 완료 후 결정.
