## A. 시스템 아키텍처

### 1. Remote Cortex — UE5(Body) + Python(Brain) 분리
- **문제**: LLM·RAG·TTS·ASR을 엔진 안에서 돌리면 VR 프레임이 깨지고, Python ML 생태계를 C++에서 못 쓴다.
- **해결**: UE5는 렌더·물리·결정론 실행만, Python 서버 3개(:8000 인지 / :8001 TTS / :8002 ASR)가 추론 전담. W03부터 불변.
- **단점**: 매 요청 네트워크 왕복 지연, 서버 3개+Ollama 운영 복잡, 상태가 두 프로세스에 분산.
- **대안**: UE5 내장 추론(NNE), 클라우드 API 직접 호출.
- **채택 이유**: Python ML 스택을 그대로 쓰면서 엔진은 실행만 남기는 유일한 경로. 지연은 계층 분담(§2·§6·§16)으로 흡수.

### 2. 3계층 두뇌 모델 — 대뇌(LLM)·소뇌(SLM)·척수(C++)
- **문제**: LLM은 초 단위인데 NPC는 피격에 즉시 반응해야 함. 전부 LLM이면 "전투 턴에 금붕어", 전부 C++면 자율성 없음.
- **해결**: 대뇌=플래너 8B+e4b(전략) / 소뇌=파인튜닝 e4b(hot loop) / 척수=C++ 반사 테이블·전투 셀렉터(0ms). W05 확립 후 모든 작업의 판단 기준.
- **단점**: 층 간 정합 비용(반사를 LLM이 모름), 경계가 시간에 따라 이동, 상태 소유권 충돌.
- **대안**: 단일 LLM 긴 컨텍스트, Utility AI/GOAP 순수 C++, 정책 캐시(원안).
- **채택 이유**: "매 틱 LLM 호출 불가"가 출발점. 실측 e4b warm 1.1s·12B cold 11s가 계층 분담 필요성을 확인.

### 3. WebSocket + MessageEnvelope 단일 채널
- **문제**: 서버→UE5 푸시 필요, NPC N개 동시 송신, 응답 순서 비보장.
- **해결**: UE5 내장 WebSockets + FastAPI WS. 모든 메시지 `MessageEnvelope{msg_id,type,payload}` 래핑, 채널 `/ws/llm` 하나. msg_id/request_gen으로 수신 측 매칭.
- **단점**: 소켓 하나 끊기면 전부 끊김, 타입 추가 시 3곳 동시 수정 안 하면 무음 무시, 동시성 버그 다수.
- **대안**: HTTP 폴링, gRPC 스트리밍, 채널 분리(초기 방식).
- **채택 이유**: 플러그인 0개로 양방향 푸시. 라우팅 책임을 Python 한 곳에 두기 위해 단일화.

## B. 인지 엔진 (Python)

### 4. FastAPI + LangGraph 멀티 에이전트
- **문제**: 발화 하나에 해석→대사→액션 추출→검증이 순차 필요, 실패 시 되돌아가야 함. 단일 프롬프트는 4B가 감당 못 함.
- **해결**: W03 4-Agent 청사진을 LangGraph 노드로: `Interface_Input→Supervisor→Dialogue→Interface_Output→Rules`, 조건 엣지 재시도 1회.
- **단점**: 노드 하나 죽으면 빈 배치 폴백(cp949 크래시 사례), LangChain 래퍼 오버헤드 실측, 노드 간 상태 계약이 암묵적.
- **대안**: 순수 asyncio 체인, AutoGen/CrewAI, 단일 프롬프트.
- **채택 이유**: 이론 골격을 그대로 그래프로 옮길 수 있고, 노드별 모델 교체·조건 재시도가 프레임워크 기능.

### 5. Pydantic v2 Rules — LLM 없는 규칙 검증

- **단점**: 새 액션마다 수작업, 정적 목록이 런타임과 어긋나면 액션이 조용히 증발, 사후 제거 방식.
- **대안**: LLM Rules(원안), JSON Schema만, UE5 측 검증만.
- **채택 이유**: 검증은 결정론·지연 0이어야 함. Pydantic strict가 공짜로 줌.

### 6. Ollama 로컬 LLM + 2-Stage 라우팅 + 계획 캐싱
- **문제**: NPC N개 매 턴 LLM 호출. 클라우드는 비용·지연, 로컬은 VRAM 16GB에 LLM+TTS+ASR+PIE. 큰 모델은 느리고 작은 모델은 액션 누락.
- **해결**: 로컬 Ollama. Stage1=파인튜닝 e4b(hot) / Stage2=플래너 qwen3:8b(plan만). 계획 캐싱("비싸게 1회, 싸게 N회"), 이벤트 트리거 재계획, prompt 없는 로드콜 웜업(342ms).
- **단점**: VRAM 예산이 모든 결정 지배(CosyVoice2 롤백·ASR CPU·KV 양자화 불가), 별칭 부재 시 조용한 500, 12B OBLITERATED rewrite 불능, thinking 토큰 함정.
- **대안**: 클라우드 API(초기 코드에 있었으나 제거), vLLM 직접, 단일 대형 모델(VRAM 불가).
- **채택 이유**: "컴퓨터가 터질 수 있기 때문" — 처음부터 로컬. 실측 e4b 2.6~3.1s vs 12B 11s가 2-Stage 절충의 근거.

### 7. Ollama format=schema 구조화 출력 직접 호출
- **문제**: e4b가 `[Action:]` 태그를 통째로 생략. langchain `with_structured_output`은 3506ms·분산 1.2~8s.
- **해결**: Ollama `/api/chat` `format=<schema>` 직접 호출 `ollama_structured()` — 1518ms(2.3배·안정). 범인은 래퍼.
- **단점**: all-optional 스키마면 필드 비움(required 강제 필요), 텍스트 프롬프트와 충돌, 클라우드 모델 미지원, 자유텍스트보다 2배 느림.
- **대안**: 자유텍스트+정규식(액션 누락), langchain 래퍼(2.3배 느림), Outlines 등 별도 스택.
- **채택 이유**: 액션 누락 0이 게임플레이 필수, 지연 차이가 실측 확정.

### 8. FAISS + MiniLM RAG 기억

## D. NPC AI (UE5 C++)

### 12. StateTree (BT에서 마이그레이션)
- **문제**: LLM이 큐를 채우는 구조에서 BT는 "큐 있나→실행" 두 노드뿐인데 BTTask 클래스·완료 경로가 난립.

- **단점**: 에디터 수작업(Transition 바인딩), 자료 적음, 마이그레이션 직후 데드코드.

- **채택 이유**: 상태+태스크+InstanceData가 큐 소비 모델에 맞음.

### 13. 비동기 액션 완료 모델 + Action Queue
- **문제**: `OnActionCompleted` 동기 호출로 큐가 한 프레임에 비워짐 — `[Move, Attack]` 직렬화 안 됨.
- **해결**: EnterState는 발행만, `bIsBusy` 폴링. 이동=`OnMoveActionCompleted`, 몽타주=`OnMontageActionEnded`, 즉시형=switch 말미. `MaxActionDuration` 워치독. `ClearActiveActionState()` 리셋 일원화.
- **단점**: 새 액션마다 4곳+완료 분기 필수(`/add-eaction`), 콜백·워치독 경합 가드, Track/Follow 예외.
- **대안**: 동기(원래), GAS(검토 기록 없음), Latent Task.
- **채택 이유**: 순차 실행 안 되면 배치 자체가 무의미. 워치독은 "완료 누락=큐 영구 정지" 안전망.

### 14. EQS + LLM 전술 위치 결정
- **문제**: 좌표 배열을 LLM에 던지면 비효율, 순수 EQS는 성격 미반영.
- **해결**: EQS가 SAFE/OPTIMAL/AGGRESSIVE 3후보 산출, LLM은 택일만. 에셋 2개 고정+Named Parameter. `request_gen`으로 stale 차단, 실패도 폴백 반환.
- **단점**: Named Parameter는 Test Score Factor만 바인딩 가능, LLM 왕복 수백 ms, gen 규칙 위반 시 영구 고착.
- **대안**: 좌표 직접, 순수 EQS 스코어링, NavMesh 랜덤.
- **채택 이유**: "계산은 EQS, 선택은 Python" 분담. 7개 난립 후 2개로 정리.

### 15. AIPerception + EmergencyReport 배치
- **문제**: 매 이벤트 전송 시 트래픽 폭주, 연타마다 위험 신호.
- **해결**: AIPerception(시야·주변시·진영). 0.2~0.5초 창에 NPC별 1회 배치, LastHitTime 2초 가드, 변화 시만 전송. `ComputePerceptionDanger()` 단일 헬퍼.

- **채택 이유**: 이벤트+배치가 트래픽·반응성 절충점.

### 16. C++ 척수반사 테이블 (SLM Reflex 대체)
- **문제**: SLM Reflex는 raw 전환해도 330ms + VRAM, 결과는 Attack/Dodge/Flee 몇 개로 수렴.

### 17. DiceSystem + 전투 셀렉터

## E. 음성

### 18. TTS — OpenVoice v2 + MeloTTS
