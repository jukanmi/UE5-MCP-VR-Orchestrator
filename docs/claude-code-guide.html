00

골든 워크플로우 — 종합 결론

여러 출처를 관통하는 "가장 안정적으로 좋은 결과를 내는" 표준 루프. 작은 작업은 건너뛰고 바로 시키되, 멀티파일·고위험·생소한 코드일수록 이 4단계를 지킬수록 한 번에 끝납니다.

01 · EXPLORE

탐색 (수정 금지)

Shift+Tab으로 플랜 모드 진입. 파일을 읽고 질문만 하며 코드는 건드리지 않게 합니다. 탐색이 길어질 땐 서브에이전트로 격리.

plan mode · "use subagents to investigate X"
02 · PLAN

계획에 공들이기

구현 계획을 글로 받아 직접 다듬습니다. 큰 기능은 SPEC.md로 떨어뜨려 두면 새 세션에서 깨끗한 컨텍스트로 실행 가능.

"create a plan" · /effort max · 2nd Claude 리뷰
03 · IMPLEMENT

구현 + 자가검증

플랜 모드 해제 후 계획대로 구현하게 하고, 같은 프롬프트 안에서 테스트·빌드를 돌려 통과할 때까지 반복하도록 지시.

auto-accept · "run tests & fix until green"
04 · VERIFY → COMMIT

독립 검증 후 커밋

새 컨텍스트의 서브에이전트로 diff를 리뷰(/code-review)시키고, 증거를 확인한 뒤 설명형 메시지로 커밋·PR.

/simplify · /code-review · "commit & open a PR"
💡

오버헤드 판단 기준: "diff를 한 문장으로 설명할 수 있다"면 계획을 건너뛰고 바로 시키세요. 계획은 접근법이 불확실하거나 · 여러 파일을 건드리거나 · 익숙하지 않은 코드일 때 가장 값집니다.

01

컨텍스트 관리 — 가장 근본 자원

컨텍스트 윈도우는 디스크 공간처럼 차오릅니다. 차오를수록 클로드가 앞 지시를 "잊고" 실수가 늘어나며 토큰도 더 먹습니다. 토큰을 자산처럼 관리하는 것이 파워유저의 1번 습관입니다.

📊/context 로 토큰 가시화

효과 높음중급

세션 중간에 한 번은 /context를 돌려 200k를 어떻게 쓰고 있는지 확인하세요. 모노레포 기준 새 세션이 베이스 ~20k(10%)를 먹기도 합니다. "남은 공간"을 알아야 언제 비울지 판단됩니다.

/context # 메시지·파일·도구별 토큰 점유 확인

🧹/clear 를 과감하게, 자주

효과 최상입문

무관한 작업 사이에는 /clear로 컨텍스트를 완전히 리셋. 실무자들은 /compact를 신뢰하지 않습니다 — 자동 압축은 불투명하고 손실이 큽니다. 깨끗한 세션 + 더 좋은 프롬프트가 거의 항상 이깁니다.

/clear # 리셋 후 /catchup # 브랜치 변경 파일만 다시 읽힘(커스텀)

📝"문서화 후 /clear" 패턴

효과 높음고급

긴 작업은 클로드에게 현재 계획·진행 상황을 .md로 덤프시키고 /clear 한 뒤, 새 세션에서 그 파일을 읽고 이어가게 합니다. 컨텍스트 밖에 "영속 메모리"를 만드는 기법.

  • 대형 리팩터·다세션 작업에 필수
  • SPEC.md / PROGRESS.md로 분리

💬/btw — 컨텍스트 안 늘리는 질문

효과 중간입문

클로드가 일하는 도중 곁가지 질문은 /btw로. 단일 턴·도구호출 없음·전체 대화 맥락은 유지하면서 답은 대화 기록에 남지 않아 컨텍스트가 깨끗하게 유지됩니다.

/btw 이 retry 로직이 정확히 뭘 하지?

⏪체크포인트로 되감기

효과 높음중급

모든 프롬프트가 체크포인트입니다. Esc Esc 또는 /rewind로 대화/코드/둘다를 이전 상태로 복원하거나 특정 지점부터 요약. "위험한 시도 → 실패하면 되감기"가 가능해집니다.

⚠

클로드의 변경만 추적합니다 — git을 대체하지 않습니다.

♻️압축은 통제해서

효과 중간고급

꼭 압축해야 한다면 /compact <지시>로 초점을 주세요(예: "API 변경에 집중"). CLAUDE.md에 "압축 시 수정 파일 목록·테스트 명령은 반드시 보존"을 적어두면 핵심이 살아남습니다. PostCompact 훅으로 핵심 지시 재주입도 가능.

/compact Focus on the API changes
🧠

실무자 통찰: "you're absolutely right!" 같은 아부가 자주 보인다면 버그가 아니라 당신이 루프에 너무 깊이 들어가 있다는 신호입니다. 목표는 위임하고 떠나는 것(shoot & forget) — 과정이 아니라 최종 PR로 도구를 평가하세요.

02

💰 토큰 절약 — 한 번 배워 오래 써먹기

토큰 비용은 컨텍스트 크기에 비례합니다. 공식 데이터 기준 평균 ~$13/개발자/활동일, 월 $150–250. 아래는 공식 "비용 관리" 문서 + 실무 노하우에서 추린, 한 번 세팅하면 계속 효과 보는 절약 기법입니다.

📈/usage · /cost 로 먼저 측정

절약 기반입문

아끼려면 먼저 어디서 새는지 봐야 합니다. /cost는 세션 토큰·비용, /usage는 플랜 한도와 스킬·서브에이전트·플러그인·MCP별 사용 비중까지 분해(d/w로 24시간/7일 전환). 상태줄로 상시 표시도 가능.

/cost # 이 세션 토큰·비용 /usage # 한도 + 주체별 사용 비중(d/w)

🎚️모델 분리 (가장 큰 절약)

절약 최상입문

대부분의 코딩은 Sonnet으로 충분하고 Opus보다 쌉니다. Opus는 복잡한 설계·다단계 추론에만. 단순 서브에이전트는 model: haiku. /model로 세션 중 전환. 커뮤니티 보고 기준 50–70% 절감.

/model sonnet # 기본은 Sonnet # 서브에이전트 frontmatter: model: haiku

🪝출력 필터 훅 (압도적)

절약 최상고급

클로드가 1만 줄 로그를 통째로 읽는 대신, PreToolUse 훅이 ERROR만 grep해서 돌려주게 하면 수만 토큰 → 수백 토큰. 테스트 출력도 실패만 남기면 됩니다. 공식 문서가 직접 제시하는 패턴.

# 테스트 실행 시 실패 라인만 통과 cmd =~ ^(npm test|pytest|go test) → $cmd 2>&1 | grep -A5 -E 'FAIL|ERROR' | head

📜CLAUDE.md → 스킬로 이전

절약 높음중급

CLAUDE.md는 매 세션 통째로 로드됩니다. PR 리뷰·DB 마이그레이션 같은 특정 워크플로우 지시는 무관한 작업에서도 토큰을 먹어요. 그런 건 온디맨드 스킬로 옮기고 CLAUDE.md는 200줄 이하로 유지.

🧠확장 사고(thinking) 조절

절약 높음중급

thinking은 output 토큰으로 과금되고 기본 예산이 수만 토큰일 수 있습니다. 깊은 추론이 필요 없는 단순 작업은 /effort를 낮추거나 /config에서 끄거나 예산을 직접 낮추세요.

/effort low # 쉬운 작업 MAX_THINKING_TOKENS=8000 # 예산 상한

⏱️프롬프트 캐시 5분 룰

절약 중간중급

반복 컨텍스트는 자동 캐싱되지만 캐시 TTL은 약 5분. 그보다 오래 자리를 비우면 다음 메시지가 전체 컨텍스트를 처음부터 재처리합니다. 잠깐 자리 뜨기 전 /compact 또는 /clear로 비용 스파이크 예방.

🔌MCP 오버헤드 줄이기

절약 중간중급

MCP 도구 정의는 기본 deferred(쓰기 전까진 이름만 로드)지만, 안 쓰는 서버는 /mcp로 비활성화하세요. 상태 없는 도구는 CLI(gh·aws·gcloud)가 per-tool 리스팅이 없어 더 효율적. /context로 점유 확인.

/mcp # 안 쓰는 서버 비활성화

🧭코드 인텔리전스 플러그인

절약 중간입문

타입 언어라면 LSP 플러그인이 "정의로 이동" 한 번으로 grep + 여러 후보 파일 읽기를 대체합니다. 불필요한 파일 읽기를 줄여 토큰을 아끼고, 편집 후 타입 에러를 자동 보고해 컴파일 없이 실수도 잡아줍니다.

🕵️장황한 작업은 서브에이전트로

절약 높음중급

테스트 실행·문서 페치·로그 처리처럼 출력이 큰 작업은 서브에이전트에 위임하면 장황한 출력은 거기 머물고 요약만 메인으로 돌아옵니다. 또 정보는 붙여넣지 말고 @파일 참조 / 재사용 정보는 .md·.yaml로 쪼개 온디맨드 로드.

⚠️

에이전트 팀 주의: Agent teams는 팀원마다 별도 컨텍스트를 유지해 플랜 모드에서 표준 세션 대비 ~7배 토큰을 씁니다. 쓸 거면 팀원은 Sonnet, 팀은 작게, 끝나면 정리. 기본 비활성(CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1).

03

검증 — 단 하나만 한다면 이것 ★

공식 팀이 못 박은 "이 가이드에서 가장 임팩트 큰 단 하나의 팁". 클로드는 "끝난 것 같으면" 멈춥니다. 스스로 읽을 수 있는 합/불 신호(테스트·빌드·린트·스크린샷)를 주면 루프가 스스로 닫히고, 당신이 검증 루프가 될 필요가 없어집니다 = 자리를 비워도 되는 세션. (재작업을 막아 토큰도 아낍니다.)

✅검증 기준을 프롬프트에 박기

효과 최상입문

"이메일 검증 함수 만들어줘"가 아니라 예시 케이스 + "구현 후 테스트를 돌려라"까지. 합/불이 나오면 클로드가 통과할 때까지 알아서 반복합니다.

validateEmail 작성. 케이스: a@b.com=true, "x"=false, u@.com=false. 구현 후 테스트 실행.

🖼️UI는 눈으로 검증 (Chrome 확장)

효과 최상중급

프론트엔드 작업엔 Claude Code Chrome 확장이 필수. "브라우저 없이 사이트를 잘 만들 엔지니어는 없다." 클로드가 스크린샷을 찍어 원본 디자인과 비교하고 차이를 좁힙니다. 데스크톱 앱은 웹서버 자동 기동·내장 브라우저 테스트 지원.

[디자인 첨부] 이대로 구현하고, 결과를 스크린샷 찍어 원본과 차이를 나열한 뒤 수정해.

🚦정지 강도 단계화

효과 높음고급

검증을 "얼마나 강하게 멈출지"로 단계화하세요. 무인 실행을 진짜로 끝까지 가게 만드는 건 뒤의 두 개입니다.

  • 한 프롬프트: "검증 돌리고 반복해"
  • 세션 전체: /goal 조건 — 매 턴 평가자가 재확인
  • 결정적 게이트: Stop 훅이 통과 전까지 종료 차단
  • 제2의 눈: 검증 서브에이전트가 결과를 반박 시도

✨/simplify 로 품질 한 번에

효과 높음중급

변경 후 아무 프롬프트 뒤에 /simplify를 붙이면 병렬 에이전트들이 재사용성·품질·효율·CLAUDE.md 준수를 한 패스로 리뷰합니다.

이 변경 적용하고 그다음 /simplify 실행해

🔍적대적 리뷰 단계

효과 높음고급

"완료"로 치기 전, 새 컨텍스트의 서브에이전트에게 diff만 주고 계획 대비 갭을 보고하게 합니다. 만든 본인이 아닌 신선한 모델이 채점.

서브에이전트로 diff를 PLAN.md와 대조해 — 모든 요구사항 구현·엣지케이스 테스트 여부만. 갭만 보고.
⚠

리뷰어는 시키면 늘 뭔가 찾아냅니다. 정확성·요구사항에 영향 주는 갭만 보라고 못 박지 않으면 과잉 엔지니어링으로 흐릅니다.

🧾증거를 요구하라

효과 중간입문

"됐다"는 주장 대신 증거를 받으세요 — 실행한 명령과 출력, 테스트 결과, 스크린샷. 다시 돌려보는 것보다 증거 확인이 빠릅니다.

  • "Prove to me this works" — main↔브랜치 동작 diff
  • "Grill me on these changes, don't PR until I pass"
🎯

트러스트-검증 갭(흔한 실패): 그럴듯해 보이지만 엣지케이스를 놓친 구현. 검증할 수 없으면 배포하지 않는다를 원칙으로. 검증은 도메인마다 다릅니다 — bash·테스트·시뮬레이터·브라우저. 도메인별 검증에 투자하는 것이 가장 남는 장사입니다.

04

계획 · 추론 강도

계획에 쏟은 노력이 구현 품질을 결정합니다. 잘못된 길로 코드를 쏟아내는 것이 토큰 낭비의 가장 큰 원인 — 계획으로 그 재작업을 막는 게 곧 절약입니다.

🗺️플랜 모드로 정렬 후 시작

효과 최상입문

Shift+Tab으로 진입(또는 /plan). 계획에 노력을 부어 클로드가 원샷 구현하게 합니다. 뭔가 어긋나는 순간 중간에 고치지 말고 곧장 플랜 모드로 돌아가 재계획하는 게 더 빠릅니다. Ctrl+G로 에디터에서 직접 계획 편집.

  • 한 클로드가 계획 → 다른 클로드가 staff 엔지니어로 리뷰
  • 5개 이상 파일·고위험(인증/결제/마이그레이션)이면 거의 항상 사용

🧠Opus + thinking 를 기본으로

효과 높음입문

팀의 논리: "더 크고 느려도 덜 잡아줘도 되고 도구 사용이 좋아 결국 더 빠르다." 덜 steer + 더 나은 도구 사용 = 작은 모델보다 총소요가 짧음. (단, 비용 민감하면 02번 모델 분리와 균형을.)

🎚️/effort 로 추론 강도 조절

효과 중간중급

4단계: low(빠름)·medium(기본)·high·max. 팀은 high를 기본으로 쓰고, 난해한 디버깅/설계엔 /effort max. max는 사용량을 빨리 태우니 세션 단위로 켭니다.

/effort max # 어려운 문제에서 끝까지 추론

🎤클로드가 당신을 인터뷰하게

효과 높음중급

큰 기능은 최소 프롬프트로 시작해 AskUserQuestion으로 당신을 인터뷰하게 하세요. 미처 생각 못 한 엣지케이스·트레이드오프를 끌어내고 끝에 SPEC.md로 정리. 그 뒤 새 세션에서 깨끗하게 실행.

[간단 설명]을 만들고 싶어. AskUserQuestion으로 나를 자세히 인터뷰해. 어려운 부분 위주로 파고들고, 끝나면 SPEC.md로 완전한 사양을 써.
05

프롬프트 기법

지시가 정밀할수록 교정이 줄어듭니다(= 토큰도 줄어듭니다). 클로드는 의도를 추론하지만 마음을 읽진 못합니다 — 파일·제약·예시 패턴을 가리켜 주세요.

🎯구체적 컨텍스트 4종

효과 최상입문

막연함을 정밀함으로 바꾸는 4가지 축(막연한 "코드베이스 개선해줘"는 광범위 스캔을 유발해 토큰을 태웁니다):

  • 범위 지정: 어느 파일·어떤 시나리오·테스트 선호
  • 출처 지목: "ExecutionFactory의 git 히스토리를 보고 요약"
  • 기존 패턴 참조: "HotDogWidget.php를 본떠서…"
  • 증상 기술: 증상 + 추정 위치 + "고쳐진 상태" 정의

📎풍부한 입력 주입

효과 높음입문

설명하지 말고 직접 주세요:

@src/auth/session.ts 이 패턴을 따라줘 # 이미지: 복붙/드래그앤드롭으로 첨부 # URL: 문서 링크 (/permissions로 도메인 허용) cat error.log | claude # 파이프 주입

🥊첫 해법을 받아들이지 마라

효과 높음중급

더 잘하게 밀어붙이는 프롬프트:

  • "Knowing everything you know now, scrap this and implement the elegant solution" — 평범한 1차 시도 뒤에 강력
  • "Grill me on these changes, don't PR until I pass"
  • "Prove to me this works"

🌀막연함도 도구다

효과 중간중급

탐색 단계라 교정 비용을 감당할 수 있을 땐 일부러 막연하게: "이 파일에서 뭘 개선하겠어?" 같은 질문이 당신이 물어볼 생각조차 못 한 것을 끌어냅니다. 제약은 나중에 걸어도 됩니다.

🎙️말로 입력 (3배 빠름)

효과 중간입문

클로드 코드 팀 코딩의 상당수가 음성. 말하면 타이핑보다 ~3배 빠르고, 그 결과 프롬프트가 더 상세해집니다. CLI /voice 후 스페이스바 홀드, macOS는 fn×2.

06

CLAUDE.md · 메모리

CLAUDE.md는 매 세션 로드되는 "리포지토리의 헌법". 매뉴얼이 아니라 가드레일로 다루는 것이 핵심입니다. 길면 클로드가 절반을 무시하고 토큰도 낭비합니다(200줄 이하 권장).

📜매뉴얼 아닌 가드레일로

효과 최상중급

/init로 시작해 클로드가 틀리는 것만 점진적으로 추가. 각 줄마다 "이걸 빼면 클로드가 실수할까?"를 묻고 아니면 삭제. 실무 모노레포도 13KB 선에서 엄격 관리합니다.

  • 포함: 못 맞추는 bash 명령, 기본과 다른 코드 스타일, 테스트 방법, 레포 에티켓, 환경 quirk
  • 제외: 코드 읽으면 아는 것, 표준 관례, 자주 바뀌는 정보, 장황한 설명

🚫안티패턴 3종

효과 높음고급

실무자가 꼽은 흔한 실수:

  • "Never"만 쓰지 마라: 부정형만 주면 그 플래그가 꼭 필요하다 믿을 때 막힘 → 항상 대안 제시
  • 문서를 임베드하지 마라: 매 실행에 전체 파일이 박혀 컨텍스트 폭증. 대신 언제·왜 읽을지 "영업"("FooBarError가 나면 X.md 참조")
  • 강제 함수로 활용: 명령이 장황하면 문서로 때우지 말고 간단한 bash 래퍼를 만들어 그걸 문서화 → 도구가 단순해짐

🌙/memory · /dream (자동 메모리)

효과 높음중급

/memory로 내장 메모리 설정. auto-memory가 선호·교정·패턴을 세션 간 저장(유저는 ~/.claude/CLAUDE.md, 프로젝트는 ./CLAUDE.md). auto-dream 서브에이전트가 쌓인 메모리에서 낡은 가정·중복을 정리·병합(REM 수면이 기억을 정리하듯).

/dream # 메모리 수동 정리 트리거

🔁Compounding Engineering

효과 최상고급

핵심 습관: 클로드가 틀릴 때마다 그 교정을 CLAUDE.md에 적게 한다. 매 교정이 미래의 모든 세션을 개선합니다. PR 리뷰에서 @claude 태그로 학습을 바로 반영.

// 교정 끝에 항상: "다신 그 실수 안 하게 CLAUDE.md를 업데이트해" # PR 코멘트: nit: enum 말고 literal union @claude add to CLAUDE.md

🔗AGENTS.md 동기화 · 배치

효과 중간중급

다른 AI IDE(Cursor·Codex) 호환 위해 AGENTS.md와 싱크. 배치 전략:

  • ~/.claude/CLAUDE.md — 모든 세션 공통(개인)
  • ./CLAUDE.md — 팀 공유(git 체크인)
  • ./CLAUDE.local.md — 개인 메모(.gitignore)
  • 부모/자식 디렉터리 — 모노레포 자동 병합

🗂️노트 디렉터리 기법

효과 중간고급

한 팀원은 모든 태스크·프로젝트마다 notes 디렉터리를 유지하게 하고 매 PR 후 갱신 → CLAUDE.md가 그걸 가리키게 합니다. 항상 켜진 짧은 헌법 + 온디맨드 상세 노트의 조합.

📐

분담 원칙: 거의 모든 작업에 적용 → CLAUDE.md(항상 켜짐) · 가끔만 필요 → 스킬(온디맨드) · 반드시 실행돼야 함 → 훅(결정적). CLAUDE.md는 advisory(권고), 훅은 mandatory(강제)입니다.

07

서브에이전트 · 병렬화

컨텍스트가 근본 제약이므로 서브에이전트는 가장 강력한 도구 중 하나입니다. 별도 컨텍스트에서 탐색하고 요약만 돌려받아 메인 대화를 깨끗하게 유지합니다. 그리고 진짜 생산성 도약은 병렬 세션에서 나옵니다.

🕵️탐색·리뷰는 서브에이전트로

효과 최상중급

코드베이스 조사는 파일을 많이 읽어 컨텍스트를 먹습니다. "use subagents to investigate X"로 별도 컨텍스트에서 탐색 후 요약만 받으세요. 구현 후 "use a subagent to review this for edge cases"도 강력.

서브에이전트로 인증 시스템의 토큰 갱신 처리와 재사용할 OAuth 유틸이 있는지 조사해.

👯Master-Clone > Lead-Specialist

효과 높음고급

실무자 견해: 커스텀 서브에이전트는 ① 컨텍스트를 게이트키핑하고 ② 인간이 정한 경직된 워크플로우를 강제하는 함정이 있습니다. 대신 핵심 컨텍스트를 CLAUDE.md에 두고 메인 에이전트가 자기 자신의 복제본에게 동적으로 위임(Task())하게 하세요.

🌲worktree 3~5개 병렬 (최대 언락)

효과 최상고급

"가장 큰 생산성 언락은 git worktree마다 클로드 세션 3~5개 병렬." 편집이 충돌하지 않습니다. 별칭(za/zb/zc), 탭 색상, 알림으로 방향을 잃지 마세요. "분석 전용" worktree를 하나 두는 것도 팁.

claude --worktree auth-refactor --tmux # Desktop: Code 탭에서 worktree 체크박스

📦/batch · 에이전트 worktree 격리

효과 높음고급

대형 마이그레이션은 /batch가 인터뷰 후 수십~수백 worktree 에이전트로 팬아웃 — 각자 격리·자가 테스트·독립 PR. 에이전트 정의에 isolation: worktree를 넣어도 됩니다.

/batch migrate src/ from Solid to React

✍️Writer / Reviewer 패턴

효과 높음중급

세션 A가 구현 → 세션 B(신선한 컨텍스트)가 리뷰. 방금 쓴 코드에 편향되지 않아 리뷰 품질이 올라갑니다. 변형: 한 클로드가 테스트 작성 → 다른 클로드가 통과 코드 작성.

⚙️커스텀 에이전트 정의

효과 중간고급

.claude/agents/에 .md를 두고 이름·색·도구셋·허용/차단 도구·권한 모드·모델을 지정. 단순 작업 에이전트는 model: haiku로 비용↓. 메인 기본 에이전트는 claude --agent <name>.

--- # .claude/agents/ReadOnly.md name: ReadOnly tools: Read # 읽기 전용, 편집·bash 불가 ---
08

훅 — 결정적 강제 규칙

CLAUDE.md가 "해야 한다(should)"라면 훅은 "반드시(must)". 예외 없이 매번 일어나야 하는 일에 씁니다. 출력 전처리로 토큰을 아끼는 데도 핵심(02번 참고). "클로드, 훅 하나 추가해줘"로 시작하세요.

🚧커밋 시점 게이트 (block-at-submit)

효과 최상고급

실무 1순위 전략: PreToolUse 훅이 git commit을 감싸 "테스트 통과 시에만 생기는 파일"을 확인. 없으면 커밋 차단 → 클로드가 빌드가 초록이 될 때까지 test-and-fix 루프.

🙅쓰기 시점 차단은 피하라

효과 높음고급

의도적으로 Edit/Write 차단 훅은 쓰지 않습니다. 계획 중간에 막으면 에이전트가 혼란·"좌절". 일을 끝내게 둔 뒤 최종 결과를 커밋 단계에서 검사하는 게 훨씬 효과적.

🎨PostToolUse 자동 포맷

효과 높음중급

Write/Edit 후 자동 포맷해 CI 실패를 예방. 비차단 "힌트 훅"으로 에이전트가 비효율적일 때 살짝 피드백.

"PostToolUse": [{ "matcher":"Write|Edit", "hooks":[{"command":"bun run format || true"}] }]

🪝라이프사이클 이벤트 6종

효과 중간중급

90% 셋업을 커버하는 이벤트:

  • SessionStart — 시작 때 컨텍스트 동적 로드
  • PreToolUse — bash 로깅·prod 커밋 차단·출력 필터링
  • PostToolUse — 자동 포맷·테스트
  • PermissionRequest — Slack/Opus로 라우팅
  • Stop — 긴 작업 결정적 체크·계속 nudge
  • PostCompact — 압축 후 핵심 지시 재주입
09

스킬 · 슬래시 커맨드 · MCP

"하루에 한 번 이상 하는 일이면 스킬·커맨드로 만들어라." 스킬은 MCP보다 더 큰 변화일 수 있다는 평가 — 환경을 추상화해 숨기는 대신 raw 환경을 주고 스크립트를 짜게 하는 방향이고, 온디맨드 로드라 항상 켜진 컨텍스트를 늘리지 않아 토큰에도 유리합니다.

🧩스킬 = "스크립팅"의 산물

효과 최상중급

.claude/skills/<name>/SKILL.md(폴더 + 마크다운 1개) = YAML frontmatter(name·description) + 본문 지시. /로 호출하거나 관련 맥락에서 자동 로드. 에이전트 자율성 3단계 중 ③ 스크립팅(raw 환경에 코드 즉석 작성)의 공식화.

--- # .claude/skills/api-conventions/SKILL.md name: api-conventions description: REST API 설계 규약 ---

🏅좋은 스킬 5원칙

효과 높음고급

잘 쓰이는 스킬의 공통 패턴:

  • description은 라우팅 룰처럼 — 정확한 순간에 발동되게 구체적으로
  • 결정적 작업엔 코드 — 파싱·검증·정렬은 "조심해" 대신 스크립트로
  • SKILL.md는 가볍게 — 상세는 companion 파일로 온디맨드 로드
  • 스킬 1개 = 직무 1개 — 여러 워크플로우 욱여넣지 않기
  • 추상 규칙보다 구체 예시

⭐알아둘 만한 스킬

효과 높음입문

바로 써먹는 것들:

  • 번들 내장: /simplify(품질 리뷰), /code-review(diff 버그 점검)
  • 공식 Frontend Design: 코드 전에 디자인 시스템·철학 주입
  • Doc Co-Authoring · Context Engineering · MCP Builder
  • 커뮤니티 모음: awesome-claude-skills
/skills # 현재 세션의 스킬 목록

⌨️슬래시 커맨드 = 단순 단축

효과 중간입문

자주 쓰는 프롬프트의 단축일 뿐. /catchup·/pr 정도로 최소화. 복잡한 커맨드 목록은 안티패턴 — 인라인 bash로 git status 등을 모델 호출 없이 선계산 가능. 부작용 있는 수동 전용 워크플로우엔 disable-model-invocation: true.

⚠

"매직 커맨드 목록을 외워야 일할 수 있다"면 실패. 직관적 CLAUDE.md·더 나은 도구가 우선.

🔌MCP는 "보안 게이트웨이"로

효과 높음고급

REST API를 그대로 미러링한 거대 MCP는 컨텍스트만 먹습니다. MCP의 새 역할은 auth·네트워크·보안 경계만 관리하고 비키는 것 — 소수의 고수준 도구만 노출. 상태 있는 환경(Playwright)엔 MCP, 상태 없는 도구(Jira·AWS·GitHub)는 CLI로.

claude mcp add # Notion·Figma·DB 등 연결

🛠️CLI 도구 우선

효과 높음입문

외부 서비스와 상호작용엔 CLI가 가장 컨텍스트 효율적. gh(미설치 시 비인증 API라 rate limit), aws, gcloud, bq… 모르는 CLI도 잘 배웁니다: "foo --help로 익힌 뒤 A,B,C 해결해".

"6개월 넘게 SQL을 한 줄도 안 썼다" — bq CLI 기반 분석.

🧱플러그인 (특히 코드 인텔리전스)

효과 중간입문

/plugin으로 마켓플레이스 탐색. 스킬·훅·서브에이전트·MCP를 한 번에 번들. 타입 언어를 쓰면 코드 인텔리전스(LSP) 플러그인으로 정확한 심볼 탐색 + 토큰 절약. 조직 내부 마켓플레이스를 settings.json에 체크인하면 전원 자동 적용.

권한 · 안전 (개입 줄이기)

기본은 안전하지만 10번째 승인쯤이면 그냥 클릭만 하게 됩니다. 통제를 유지하면서 개입을 줄이는 3가지 레버.

📋/permissions 사전 허용 (권장)

효과 최상입문

권한 스킵 대신 권장되는 길: 안전한 명령을 미리 허용하고 팀 settings.json에 체크인. 와일드카드 지원 — Bash(bun run *), Edit(/docs/**). 감사 가능한 allowlist를 유지하면서 프롬프트만 줄입니다.

/permissions # 안전 명령 사전 허용

🤖오토 모드 · Accept Edits

효과 높음중급

분류기 모델이 매 액션을 평가 — 안전하면 자동 승인, 위험(스코프 확대·미지 인프라)은 차단. Shift+Tab으로 모드 순환(default→acceptEdits→plan, +auto). Accept Edits는 편집만 자동 승인하고 셸은 여전히 확인.

claude --permission-mode auto -p "fix all lint errors"

📦/sandbox — OS 레벨 격리

효과 중간고급

오픈소스 샌드박스 런타임으로 파일·네트워크 격리. 안전을 높이면서 권한 프롬프트는 줄입니다. 3모드: BashTool 샌드박스+자동허용 / 샌드박스+일반권한 / 샌드박스 없음.

⏳장시간 무인 작업

효과 중간고급

아주 긴 작업은 끊김 없이 돌게: 백그라운드 에이전트로 완료 검증 / Stop 훅 결정적 체크(감사용 선호). 샌드박스 환경에선 --permission-mode=dontAsk 또는 --dangerously-skip-permissions로 차단 회피.

11

자동화 · 스케일

한 클로드를 잘 다루게 됐다면, 비대화형 모드·팬아웃·GitHub Action·스케줄로 출력을 곱하세요. 클로드 코드는 수평 확장됩니다.

⚡비대화형 claude -p

효과 높음중급

세션 없이 실행 → CI·pre-commit·스크립트에 통합. 출력 포맷으로 결과를 프로그램적으로 파싱.

claude -p "List all API endpoints" --output-format json claude -p "Analyze log" --output-format stream-json --verbose

🔀파일별 팬아웃

효과 높음고급

대형 마이그레이션은 파일 목록을 만든 뒤 루프로 claude -p를 병렬 호출. 먼저 2~3개로 프롬프트를 다듬고 전체로. --allowedTools로 무인 실행 범위를 제한.

for f in $(cat files.txt); do claude -p "Migrate $f. Return OK/FAIL." \ --allowedTools "Edit,Bash(git commit *)" done

🐙GitHub Action (가장 저평가)

효과 최상고급

그냥 "GHA 안에서 클로드 코드 실행"이지만 컨테이너·환경·샌드박싱·감사를 전부 통제. Slack/Jira/CloudWatch 알림에서 "어디서든 PR" 트리거 → 테스트 완료 PR 반환. GHA 로그를 정기 리뷰해 CLAUDE.md/CLI를 개선하는 자기개선 플라이휠.

query-claude-gha-logs --since 5d | claude -p "다른 클로드들이 막힌 지점을 보고 고친 뒤 PR 올려"

🔁/loop (로컬) · /schedule (클라우드)

효과 높음중급

/loop은 로컬에서 최대 3일 반복(노트북 켜져 있어야), /schedule은 클라우드에서 노트북 닫혀도 실행. 가장 흔한 워크플로우를 스킬 + loop로 만드는 게 강력.

/loop 5m /babysit # 리뷰·리베이스·PR 셰퍼딩 /schedule 매일 PR 변경분으로 문서 업데이트

🧰Claude Code SDK = 범용 에이전트 프레임워크

효과 중간고급

코딩 전용이 아닙니다. ①대규모 병렬 스크립팅 ②비기술 유저용 내부 챗 도구 ③새 에이전트 빠른 프로토타이핑. 비대화형은 --bare로 로컬 설정 탐색을 생략해 시작 ~10배 빠름.

🗃️멀티레포 · 세션 분기

효과 중간고급
  • --add-dir / additionalDirectories: 여러 레포 접근
  • /branch 또는 --resume <id> --fork-session: 세션 분기
  • 클라우드 세션 setup 스크립트로 의존성·환경 선설치(resume 시 생략)

✨ 편의 기능 · 숨은 명령어 · 단축키

⌨️꼭 외울 단축키

효과 높음입문
